## Presentation

Explicit invocation and target capture remain host responsibilities. Input keeps the existing monochrome capsule, system typography, 52-point height and 360-point preferred width. Improve submits the existing default instruction when the input is blank; a custom instruction uses the existing submission path. More exposes only configured presets and fills the instruction for review before submission. It adds no Explain capability or provider/model restriction. Stop uses the existing matching-generation cancellation path; applying has no cancel control. The completed proposal stays in a selectable imrse-owned preview above explicit Replace/Discard controls. Nothing in the view writes streamed output into an external field. Undo remains conditional on the host's confirmed receipt availability.

The app panel accepts an optional captured selection rectangle in global AppKit screen coordinates. This is a layout hint, never target identity or permission to write. Invalid, empty or off-screen geometry falls back to the captured screen's bottom-center region. The whole panel, including shadow space, is clamped inside the usable screen. The original trailing/bottom anchor survives phase contractions, preview expansion and clipboard focus handoff, rather than following generated text or the pointer. Screen clamping takes precedence near an edge. A newly invoked interaction captures a new anchor.

Conservative implementation defaults, not new user selections: an 8-point selection-to-surface gap, 20-point screen-edge inset, 24-point fallback panel-bottom inset, 28-point control hit height, a 216-point proposal surface including its 52-point action row, and immediate panel placement/resizing. Existing loader assets and Reduced Motion behavior remain in place; invocation is immediate. Input width is capped to the available screen space, including the host's shadow padding. Proposal text scrolls inside a fixed region rather than resizing controls as its length changes.

## Remaining integration and validation

The view consumes the core owner's proposal contract: `PillPhase.proposal(requestID)`, `PillModel.previewText`, `replaceProposal()`, `discardProposal()` and generation-only `stopGeneration(_ requestID: UUID)`. Stop binds the UUID from its rendered processing phase and preserves typed neutral cancellation feedback instead of dismissing the panel before the matching callback. A stale rendered Stop cannot cancel a later request. Typed `failureKind` distinguishes cancellation, lost targets, generation failure, replacement failure and pending clipboard recovery, while the safe message remains available in full. A legacy nil kind receives generic failure presentation. The engine, bridge and model own immutable proposal identity, explicit commit-time revalidation, cancellation, receipts and recovery. The view neither parses error strings nor resets an uncertain transaction or reports it as success.
