# Pinned custom-input session (experimental, not yet native-qualified)

User contract: at double-Control invocation, capture an immutable copy of the selected text. Instruction entry operates on that copy. Submission sends that selected text and instruction to the chosen provider, not the full-field baseline. Cancellation discards the session. Return targets the original field, never whichever field happens to be current.

The existing AX capture already copies selected text before the panel appears. It also supports selected-range plus whole-value substring evidence when AXSelectedText itself is unavailable. This is preferable to Cmd-C because it leaves the user's clipboard untouched. The new instruction return ticket separately pins capture ID, panel instance, original process incarnation, and a bounded whole-field baseline. The existing target handle retains exact AX anchor/window/document/range checks.

During the token's bounded lifetime, only an absent AX focus value while the exact instruction panel owns keyboard focus is treated as authorized own-UI defocus. Observed alternate anchors, application/window/document/text/selection changes and read errors retain fail-closed behavior. At handoff the panel is hidden and must no longer be key. A maximum 500 ms read-only wait may resolve absent original focus, never a different anchor. Full original baseline, selection and process/window identity must match before dispatch. This is pinned-snapshot intent, not a claim of uninterrupted focus history.

The normal instruction session retains the existing route chooser: qualified compatible web fields use the guarded clipboard transaction when enabled; proven native routes remain available, including with compatibility OFF. No native setter is replayed as a paste after dispatch. Compatibility permission, event-posting permission, supported surface/style, exact baseline/selection, clipboard ownership, final cancellation/TTL and one-post checks still apply. Post-paste uncertainty never authorizes replay. Clipboard restoration remains proof- and ownership-bound.

Complete generated output is retained in memory for a bounded explicit-copy accessor if automatic replacement cannot be verified. No silent clipboard write or automatic fallback destination occurs. UI wiring must disclose uncertainty and pending clipboard recovery before an explicit Copy action; copying over a pending owned clipboard can abandon restoration authority. Backend output retention alone is not a new visible Copy interface.

Cmd-C fallback is not yet wired. Where AX lacks both selected-range/whole-value evidence, copying may obtain model input but cannot prove a safe automatic destination. Such a tier needs explicit manual output, not blind paste. No capture fallback should read old clipboard contents as if they were freshly copied text.

The current running user process has a retained pending clipboard transaction. Source/unit work does not migrate or recover that memory. Do not restart it or overwrite the clipboard without the owner's decision. Native end-to-end testing remains blocked until that state is safely resolved.

Source admission expires after 180 seconds in instruction entry, with a monotonic check both on Submit and immediately before provider invocation. This is not a hard provider timeout or secure-memory erasure claim: an already-started provider task may retain its immutable request until it settles. Complete failed-application output has a separate 180-second bounded backend retention window. No user-accessible fallback UI is added in this change.
